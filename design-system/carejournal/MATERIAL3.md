### 已实施：操作按钮专项

- 图标按钮改为透明/浅色/实色圆形三档；普通操作不再有常驻方形包边。
- 主文字按钮使用胶囊形，次按钮以轻色调而非边框区分。
- 导入来源、报告删除/重新识别、指标新增、图表添加/管理、材料拍照/导入和方案排序完成采用图标，保留可访问名称与提示。
- 保存、危险确认、空状态首次操作、模式选择等保留必要文字；不删除导航标签和筛选值。
- 筛选图标保留选中数量并暴露展开状态；修正主按钮、危险操作与筛选数量在深色模式的前景色。
- 本专项不改变导航目的地、数据规则、列表手势或应用启动图标。

## 1. 设计结论

**保留暖纸色与陶土色品牌，把界面从“许多带边框的小卡片”整理为“清晰的色调层级、可读的记录、统一的操作语言”。**

病程记是长期使用的资料整理工具，不应改成医院管理后台，也不应加入营销式大标题、玻璃效果、装饰渐变或持续动画。设计应服务于三个任务：记录今天发生的事、找到一份报告、看懂某项数据的变化。

Material 3 在这里提供语义色、字阶、组件状态、触控尺寸和自适应布局，而不是强制使用默认紫色或把每个页面做成同样的模板。

### 技术边界

- 当前是 React 19、原生 CSS、React Router、ECharts 的共享 Web 界面，配合 Capacitor、HarmonyOS 和 Tauri 平台桥接；不是 Compose 页面。
- 保留现有框架、数据模型、平台能力和业务流程，不因 skill 的 Compose-first 建议重写客户端。
- 优先用 CSS 自定义属性和现有 React 组件实现 Material 3 设计语言。`@material/web` 处于维护模式，不作为本轮整体迁移目标。
- Web 端状态过渡不声称具有 Compose M3 Expressive 的完整能力。
- `MASTER.md` 的信息优先、单一主操作、零数据状态、左滑/长按、返回上下文规则继续保留。

## 3. 设计原则

1. **安静而明确**：品牌色引导动作，正文负责表达信息；不把所有分类、图标和标题都涂成主色。
2. **密度来自结构，不来自小字**：分组、折叠、详情承接复杂信息，不能以 8–11px 文字换取首屏容量。
3. **先浏览，再编辑**：保留点击查看、左滑单项操作、长按批量/排序；另外提供键盘与非手势入口。
4. **状态比装饰重要**：异常、未完成、识别失败必须可读；不以颜色或图标单独表达状态。
5. **适应窗口，而不是放大手机**：桌面增加有意义的支持区，不把列表横向拉宽或机械分成多列。

## 4. 视觉规范

### 4.1 色彩：暖色品牌 + Material 3 语义角色

保留陶土色品牌基调。先完成角色映射和对比度修正，再决定是否用 Material Color Utilities 从品牌种子生成完整色板；现有配色不能直接宣称为算法生成的标准 M3 色板。

| 建议角色 | 用途 | 与当前变量的关系 |
|---|---|---|
| `--md-sys-color-primary` / `on-primary` | 主按钮及按钮上的文字/图标 | 现有 `primary-strong` 是主要操作色，迁移时按实际用途映射，不机械照变量名替换 |
| `primary-container` / `on-primary-container` | 选中导航、轻强调容器 | 承接 `primary-soft` 的意图 |
| `secondary-container` / `on-secondary-container` | 次要操作、筛选或辅助容器 | 降低与主操作的竞争 |
| `surface` / `on-surface` | 页面背景与正文 | 保留暖色，不使用纯白/纯黑反差作为默认层级 |
| `surface-container-low/standard/high` | 内容、导航、弹层的色调层级 | 替代只有两个 surface、再靠统一阴影分层的方式 |
| `on-surface-variant` | 日期、来源、说明 | 承接 `muted`，仍须符合文字对比度要求 |
| `outline` / `outline-variant` | 输入边界 / 装饰分隔 | 不把所有边界都画成同样深浅 |
| `error` / `on-error` / `error-container` | 删除、识别错误、明确的异常提示 | 承接 `danger`；浅深主题分别定义正确前景 |
| 项目扩展 `success`、`warning` 及其前景/容器 | 完成、注意、待处理 | M3 核心色角色之外的业务语义，不冒充标准角色 |

迁移期保留旧变量作为兼容别名，逐项确认消费端角色后替换；禁止一次全局字符串替换。

验收要求：普通文字至少 4.5:1，大字至少 3:1；有意义的图标、控件边界和自定义焦点指示至少 3:1。不要以降低整个按钮透明度的方式设计禁用态后仍声称其文字达到普通态标准。

分类色与错误色分开：方案类型、报销类型和图表序列可以有多色，但必须限定在对应分类/可视化范围，配有文字或线型，不扩散为页面操作色。已有事件分类的颜色含义不应在一次视觉改版中悄悄改变。

### 4.2 字体与字阶

保留适合中文阅读的字体栈，不强制远程加载 Roboto。M3 支持品牌与正文的字体定制；当前优先保证离线、中文和多平台显示稳定。CSS 写出字体名不等于已经安装或打包了该字体。

| 用途 | 建议字号 / 行高 | 字重 |
|---|---|---|
| 详情/编辑标题 | 22 / 28px | 600 |
| 页面内区块标题 | 18 / 24px，项目扩展 | 600 |
| 记录主标题 | 16 / 24px | 500–600 |
| 正文、主要输入内容 | 16 / 24px | 400 |
| 列表元信息、表单说明 | 14 / 20px | 400–500 |
| 按钮与筛选标签 | 14 / 20px | 500–600 |
| 导航标签、日期辅助信息 | 12 / 16px | 500 |

以 `rem` 表达字阶，以上 px 是 16px 根字号下的基准。无需把 M3 的 15 档字阶全部使用，也不为了匹配规格加入无用的大标题。

- 核心医疗结果、日期、数量、进度使用 `tabular-nums`，不要把医学数值做成装饰性大数字。
- 字重不再普遍使用 800；用间距和字阶区分标题、正文与状态。
- 核心操作和内容不使用低于 12px 的字；日历放不下时减少摘要，而不是继续缩小。
- 中文不照搬英文宽字距，不用大面积全大写辅助标题。
- 长医院名称、药品名可换行或在详情完整显示；指标数值与单位不能被省略号截断。

### 4.3 间距、形状与表面

采用 8px 主节奏、4px 微调：`4 / 8 / 16 / 24 / 32 / 48`。屏幕内边距手机 16px、平板 24px、桌面 24–32px；区块间距 24px，列表内容内边距 12–16px，图标与标签间距 8px。

| 元素 | 建议形状与表面 |
|---|---|
| 普通列表项 | 0–12px，平坦表面或分隔线，不使用通用投影 |
| 独立任务/图表容器 | 12–16px，低层级色调容器 |
| 主按钮 | 全圆角；按按钮族统一，不把输入框也做成胶囊 |
| 导航选中指示 | 图标后的胶囊或侧栏完整行指示 |
| 标准图标按钮 | 圆形交互容器，必要时使用 tonal/filled 变体 |
| 输入与选择器 | 使用同一字段形状，先保留 8–12px 的项目定制，再按实测调整 |
| 弹层与底部 Sheet | 28px；底部 Sheet 只保留上方圆角 |

默认不同时叠加“实线边框 + 重阴影 + 强色底”。输入边框、弹层阴影和可视化边界各有用途，不应一律移除。触控目标优先达到 48×48px；桌面密集操作可以保留 44px，狭窄日历格单独按布局验证，不挤出七列。

### 4.4 状态与动效

- 按钮统一 filled、tonal、outlined、text 四档；一个任务区域只有一个最高强调操作。
- hover/pressed 用轻量状态层；不通过字体变粗、元素变大或弹跳制造布局位移。
- 普通反馈 150–200ms，页面/弹层过渡 200–300ms；只使用 opacity/transform 等合适属性。
- 保留减少动效设置，运行中的识别/同步同时有进度文字，不能仅靠旋转图标反馈。
- 表单失败在对应字段或任务区域说明原因与下一步；不要通过 Snackbar 承载唯一的关键错误信息。

## 5. 图标规范

### 5.1 图标库决策

**首批保留已安装的 Lucide，以统一语义、尺寸和触控容器为主；长期若追求更完整的 M3 风格，再统一迁移到本地 Material Symbols Rounded SVG。**

现有 SVG 已一致，换库不是第一优先级。禁止一页混用两套图标，也不要给 Lucide 描边图标简单加 `fill` 来伪造选中态。保留 Lucide 阶段使用选中容器与文字反馈；Material Symbols 阶段使用同一图形的 outlined/filled 成对资产。

Material Symbols 如实施，应选择需要的静态 SVG、本地打包并保留许可证；不依赖 Google Fonts 网络请求，不加载全量图标字体，不要求用户设备联网后才能看到关键操作。

### 5.2 语义映射

以下是选型建议，不代表已安装对应资产：

| 功能 | 当前 | Lucide 阶段建议 | Material Symbols 目标 |
|---|---|---|---|
| 病程 | `CalendarDays` | 保留 | `calendar_month` |
| 检查报告 | `ListChecks` | `FileText`，避免待办隐喻 | `lab_profile` |
| 治疗方案 | `Pill` | `ClipboardList`，覆盖非药物方案 | `assignment` |
| 图表 | `ChartNoAxesCombined` | 保留 | `monitoring` |
| 报销 | `WalletCards` | `ReceiptText`，更接近凭证任务 | `receipt_long` |
| 设置 | `Settings` | 保留 | `settings` |
| 搜索 / 筛选 | `Search` / `Filter`、`ListFilter` | 筛选统一 `ListFilter` | `search` / `filter_list` |
| 导入 / 导出 | 多个 File/Upload 图标 | 按动作统一 `FileUp` / `Download` | `file_upload` / `file_download` |
| 新建 / 编辑 / 删除 | `Plus` / `Pencil` / `Trash2` | 保留 | `add` / `edit` / `delete` |
| 重试 / 后退 / 关闭 | `RefreshCw` / 返回箭头 / `X` | 保留，返回与关闭不可互换 | `refresh` / `arrow_back` / `close` |

实际落地前验证图标导出/资产存在及小尺寸辨识度。不要凭图标名称推断它一定适合中文用户；标签仍是主要语义。

- 主要操作和导航图标 24px，行内辅助图标 20px；16px 仅用于非独立点击的次要提示。
- Lucide 默认描边 2，状态勾选可以有经过记录的局部例外；不在每个页面临时改描边。
- 纯图标按钮必须有本地化名称与提示；语义清楚的动作优先图标，保存、覆盖确认等容易歧义的动作才保留短文字。
- 状态图标必须搭配“异常”“已报销”“识别失败”等文字。
- 不给每条报告增加装饰性文件图标，避免浪费本来有限的内容宽度。
- 应用启动图标沿用 `app-icon\README.md` 的单一高分辨率来源与小尺寸专用字形，不在本轮重画品牌资产。

## 6. 布局与逐页改版

### 6.1 自适应导航

目标参考断点为 `<600 / 600–839 / 840–1199 / ≥1200px`，使用 CSS 像素，不把物理屏幕像素当成 dp。当前 720/1100px 断点可以在第一阶段保留，完成导航结构决策后再统一迁移。

| 窗口 | 建议结构 |
|---|---|
| 手机 | 首批保留原入口和顺序，只优化字阶、触控与选中态；后续评估“4 个主要入口 + 更多” |
| 平板 | 80–88px Navigation Rail，始终有短标签，不是只有一列无名称图标 |
| 小桌面 | Rail + 完整内容区，避免侧栏过早占用宽度 |
| 宽桌面 | 约 240px Drawer，保留全部 6 个目的地与品牌信息 |

Material 3 底部导航建议 3–5 个目的地，当前 6 项需要单独的信息架构决策。候选结构是“病程、检查、方案、图表、更多”，报销和设置从更多进入；这不是已验证的频率排序，实施前需确认是否会牺牲报销的日常可达性。

若采纳新导航：保留所有原路由和深链接，更多入口在报销/设置子页明确选中，页面内返回仍遵循原入口；不要只删去两个 Tab 或直接改硬编码索引。相关 `navIndex`、选中指示和返回动效必须一并调整。

### 6.2 页面建议

| 页面 | 改版方向 | 必须保留 |
|---|---|---|
| 病程 | 手机月份栏拆分为时间导航和操作组，确保“今天”可达；月格显示少量可读摘要及溢出数量，详细事件放在当天列表。宽屏评估月历 + 当天事件支持面板，空间不足仍上下排列 | 月份手势、日期选择、事件筛选、新建、完整事件查看和返回日期 |
| 检查 | 顶部沿用搜索 + 筛选 + 导入；宽屏可显示“导入”文字。减少外框/阴影，按日分组更清晰，异常数量保持强于普通元信息 | 日期快速索引、筛选 Chips、异常摘要、详情/编辑、来源回溯 |
| 方案 | 统一搜索工具栏和类型标签；名称为主，周期/执行日为次，长方案细节进入预览。药丸图标更换为覆盖全部治疗类型的语义 | 类型筛选、复制、排序、只读预览、再进入编辑 |
| 图表 | 收藏概览保留；选择区为低强调支持区，绘图区为主区域。手机添加入口尽量保留“添加”短标签，管理降为次操作 | 两种模式、时间范围、缩放平移、收藏/排序、事件标记、相关报告 |
| 报销 | 标题、医院日期、类型、材料完成度按稳定层级排列；“材料齐全”和“已报销”继续作为不同状态，不能看到 100% 就推断报销完成 | 材料清单、附件、重匹配、左滑标记、批量 ZIP 导出 |
| 导入 | 首选“选择图片/PDF”，拍照作为相邻次操作，文件夹为平台支持的辅助入口；队列摘要与任务行分层，缩略图只承担识别来源作用 | 平台来源能力、后台队列、进度、失败原因、批量重试与移除 |
| 设置 | 保留现有折叠组织，卡片头部只显示图标、标题、当前状态；服务商工作区减少重复边框，保存/测试权重明确 | LLM、脱敏说明、备份覆盖确认、局域网同步、地区语言、深色模式 |
| 详情与弹层 | 统一标题、关闭、滚动内容和必要底部动作；长表单评估接近全屏 Sheet，而非过短弹层里多重滚动 | 原弹层栈、数据、关闭后的原位置、未保存内容保护 |

日历现有实现已经限制用于摘要的事件集合；此次不是重新设计事件优先级，而是改善摘要可读性。若增加溢出计数，它应反映当前筛选范围内未显示的实际事件，完整内容仍在当天列表可见。

桌面 list-detail 并排只在第二阶段评估，不为纯视觉升级重构所有弹层和路由。

### 6.3 全局后台状态

当前 OCR 状态条是固定浮层，手机定位在底栏上方，但没有独立预留等高的内容空间。目标是使用统一布局变量协调底栏、后台状态区与安全区，确保最后一条记录和底部动作能滚动到可见位置。

导入页已有完整队列摘要时，可以减少重复的全局展示；离开导入页仍需有非阻塞进度与失败入口。长期任务不使用短暂消失的 Snackbar 代替。

## 7. 必须保护的行为与可访问性

- 空集合仍只有一个明确主入口；筛选无结果保留筛选工具，不冒充首次使用空状态。
- 不更改异常判定、单位、周期分组、指标标准化、报销完成逻辑和数据存储。
- 不以视觉整理为理由减少隐私告知、识别失败说明或危险操作确认。
- 左滑/长按不是唯一操作入口；键盘和非手势用户也能完成同样任务。
- Modal 增加焦点进入、圈定及关闭后的焦点还原；嵌套弹层只操作最上层。当前右滑关闭语义与底部 Sheet 的视觉方向要明确，不悄悄更换为下滑关闭。
- 编辑器退出保护未保存内容；只读详情可以保留更轻量的关闭方式。
- 200% 文字放大、英文/繁体长标签、软键盘、安全区、横屏窄高度均须检查。
- 本阶段不新增字体大小、对比度模式等设置项；先保证默认主题和系统放大可用，避免扩大业务范围。

## 8. 分阶段实施与验收

### 第一阶段：不改信息架构的视觉整理

1. 修正浅深主题操作前景、焦点与状态配色；补充语义变量兼容层。
2. 公共按钮、图标按钮、字段、Card、弹层统一形状、字阶、状态与触控目标。
3. 统一 Lucide 语义映射，保留现有导航目的地、路由和品牌资产。
4. 优化日历摘要、列表元信息、图表工具栏及全局 OCR 状态避让。

最小变更面以 `src\styles.css`、`src\App.tsx` 和直接依赖的公共组件为主；页面布局按需要调整，不碰数据服务。

### 第二阶段：自适应布局与图标体系

1. 确认手机主要入口和更多结构，再调整平板 Rail、宽桌面 Drawer 与统一断点。
2. 如选择 Material Symbols，按完整组件范围迁移并移除对应旧图标，而不是混用。
3. 按实际内容密度评估日历支持面板、检查 list-detail、长表单全屏编辑。

### 交付验收

- 窗口宽度：320px 兜底，360 / 375 / 430 / 600 / 768 / 840 / 1200 / 1600px 重点检查。
- 浅深主题的文字、图标、焦点和危险操作达到约定对比度，深色主按钮不再白字配浅底。
- 核心内容可读，日历摘要不再依赖低于 12px 的字体；溢出内容有明确入口。
- 手机没有横向溢出；图表的专用平移缩放、长筛选条与表格的必要横向滚动属于局部例外。
- 导航和后台状态不遮挡最后一条记录、确认按钮或键盘后的保存动作。
- 从图表/日历进入报告再返回，保持原入口、日期、筛选及页面状态。
- 空、少量、长列表、无匹配、识别中/失败、长文本、未配置服务均有检查样例。
- 真正实施时运行 `npm run lint`、`npm run build` 和与改动对应的现有测试；纯 CSS 改动还必须进行实际渲染检查，单元测试不能证明布局可读。
- 按钮专项以外的布局和导航仍是提案，不代表上述完整验收已执行或界面已完成全部改版。
